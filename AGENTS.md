# CyberCantina Agent Guidelines

## Architecture & Context Discipline
- **Architecture Maps (`docs/architecture/`)**: Before broad grepping, consult `docs/architecture/README.md`, `docs/architecture/CROSS_LAYER_MAP.md` (FastAPI <-> frontend API endpoints, `schema.sql` ER diagram, and package file index), `docs/architecture/BACKEND_GRAPH.md`, and `docs/architecture/FRONTEND_GRAPH.md`. Regenerate after adding routes, schema tables, or modules via `backend/.venv/bin/python scripts/generate_arch_docs.py`.
- **Modular Domain Layout & Facade Seams**: Place new domain logic in the extracted subpackages rather than re-expanding compatibility facades: `backend/app/db/repos/`, `backend/app/engine/{affective,context,cognition,char_agent,clerk}/`, `backend/app/routers/campaign_routes/`, `backend/app/wizards/char_gen/`, `frontend/src/{types,api}/`, and `frontend/src/components/{auth,character,chat,inspector,map,wizard,world}/`. When modifying code behind facades (`db/repository.py`, `db/vector_store.py`, `engine/{affective_engine,phase2_context,phase3_cognition,phase5_clerk,character_agent}.py`, `routers/campaigns.py`), preserve their re-exports and facade lookup hooks (`app.db.repository.embed_text`, `vs_module.embed_text`, `phase5_clerk.run_character_post_turn_agent`, `phase4_clerk`/`phase5_clerk.summarize_turn_chunk`, and `_resolve_facade_attr` in `routers/campaign_routes/schemas_and_gate.py`) so test `monkeypatch` seams remain intact. Keep layer boundaries compliant with `backend/tach.toml` (`tach check`) and `frontend/.dependency-cruiser.cjs` (`arch:check`).
- **4-Zone KV-Cache Economy**: Zone 1 static system context (`backend/app/engine/context/zone1_static.py`, re-exported via `phase2_context.py`) is paid on every turn. Keep injected character fields non-redundant and concise (strict domain boundaries between `core_persona`, `moral_code`, `quirks_flaws`, `communication_style`, `distinctive_features`, and `equipped`/`inventory`).
- **End-to-End Field Synchronization**: When changing a generated entity field's semantics or constraints (e.g., `"Height"` metric-only, single-item equipment), update all layers together: frontend form components & manual/offline fallbacks, backend prompt templates (`backend/app/prompts/defaults.py`), Pydantic schema `Field(description=...)`, backend fallback generators, and Zone 1 prompt rendering.

## LLM Integration & Post-Processing
- **Constrained JSON Schemas (Pydantic v2)**: Models with default field values emit `required: []` JSON Schemas, letting local 12B Ollama/llama.cpp models omit keys or emit blanks. Pass explicit `required_properties=list(schema_cls.model_fields.keys())` to `complete_structured` (`backend/app/engine/llm_client.py`) and model multi-line bullet outputs as `list[str]` arrays in LLM pass schemas rather than newline-delimited strings.
- **Never Shadow Multi-Pass Pipelines**: Do not pass an always-populated default prompt key (e.g., from `resolve_effective_prompts`) as an override flag into multi-pass wizard functions; doing so silently routes requests into legacy single-pass fallbacks.
- **Deterministic Hygiene Over Negative Prompts**: Do not spend prompt tokens forbidding HTML tags or formatting quirks ("never emit `<i>`"); sanitize deterministically in centralized Pydantic schema `@model_validator`s instead. Preserve functional prose formatting (e.g., convert `<i>`/`<em>` to Markdown `*...*` matching `renderFormattedProse` in `frontend/src/components/chat/chatHelpers.tsx`) while stripping raw markup from plain-text/chip fields and dropping chain-of-thought wrapper blocks (`<think>`, `<thought>`, `<reasoning>`, `<scratchpad>`). Match strict HTML tag patterns (`</?[a-zA-Z]...`) rather than greedy `<[^>]+>` so comparison operators (`Age < 30`) remain intact.
- **Genre-Adaptive Fallbacks**: Never hardcode single-genre (e.g., cyberpunk) defaults or few-shot examples in shared fallbacks; resolve defaults from multi-genre profiles and assign structured enums/presets (e.g., `BASELINE_MOOD_PRESETS`, CARE temperament) deterministically.

## Frontend UI & UX Contracts
- **Tag & Keyword Inputs**: Always use `TagChipsInput` (`frontend/src/components/TagChipsInput.tsx`) for tag/keyword arrays. Never bind `<input value={tags.join(", ")}>` with `.split(",").filter(Boolean)` in `onChange`, which deletes spaces and trailing commas on every keystroke.
- **Semantic Accents**: Reserve `--accent-rose` / red strictly for errors, validation failures, and destructive actions. Assistive AI extract/populate actions must use `--accent-amber` or `--accent-violet` with `Sparkles`.
- **Dynamic Node Modals & Creation Flows**: Keep primary `+ Add` headers sticky inside long node editors and scroll/focus newly appended entries into view. Separate catalog saving (`Save Character`) from optional session launch toggles (`Immediately start a campaign`).

## Feature Specifications & Lifecycle Artifacts
- **Feature Packages (`docs/features/<target_version>-<feature-slug>/`)**: Active feature requirements (`FRD.md`), architectural designs (`ARCHITECTURE.md`), pre-implementation reviews (`REVIEW.md`), and execution plans (`PLAN.md`) are colocated in versioned directories.
- **Pre-Implementation Review**: When starting work on a feature, inspect `FRD.md`, `REVIEW.md`, and `PLAN.md` in its feature folder before generating code to avoid known architectural traps and edge cases.

## Verification & Debugging
- **Character Media Path & Log Boundaries**: All character ID validation and media filesystem operations (`shutil.copytree`, `shutil.rmtree`, `FileResponse`, `unlink`, image saves) must route through `backend/app/security/media_path.py` (`validate_safe_character_id`, `safe_resolve_character_media_dir`, `safe_resolve_media_file_path`) rather than raw `Path(self.media_dir)` joins, and client-influenced log values must pass through `sanitize_log_value` (`backend/app/security/log_sanitize.py`).
- **Live Output Diagnostics**: When debugging user-reported generation issues, inspect saved rows directly in `backend/cybercantina.db` via `sqlite3` to verify whether defects stem from LLM output, fallback imputation, or frontend rendering.
- **Required Checks Before Completion**:
  - Backend: `cd backend && .venv/bin/ruff check app tests && .venv/bin/tach check` and `backend/.venv/bin/pytest backend/tests`
  - Frontend: `npm --prefix frontend run arch:check && npm --prefix frontend run build && npm --prefix frontend test`
  - Architecture docs (when modules/routes/tables change): `backend/.venv/bin/python scripts/generate_arch_docs.py`
