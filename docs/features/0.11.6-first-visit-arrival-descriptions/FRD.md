## 1. Executive Summary & Problem Statement

### 1.1 Problem Statement
1. **Rich Worldbuilding Descriptions Are Hidden Unless Players Open the Map Drawer:**
   - Authors invest time writing Atmospheric Descriptions (`location_nodes.description` and `location_containers.description`) across districts, buildings, and rooms, yet during active roleplay players only encounter prose generated by the LLM—often missing authored architectural and sensory details when entering a location or container for the first time.
2. **Re-Describing Locations via Additional LLM Calls Is Wasteful:**
   - Triggering a narrator/clerk LLM generation step on every arrival adds latency and token cost when curated, human-authored descriptions already exist on the world graph.
3. **No Shared "World Settings" Surface Across Editor & Active Campaigns:**
   - [`WorldGlobalRules`](file:///home/diegolima/Git/cybercantina/backend/app/schemas/world.py#L247) lives inside the world editor ([`WorldInspectorModal`](file:///home/diegolima/Git/cybercantina/frontend/src/components/world/WorldInspectorModal.tsx#L38)) with no campaign-accessible World Sheet, and mutating a base world during active campaigns triggers Copy-on-Write isolation ([`worlds.py`](file:///home/diegolima/Git/cybercantina/backend/app/db/repos/worlds.py#L718-L738)).

### 1.2 Proposed Solution
1. **World Settings & Campaign Independence (`FR-1`):**
   - Add a **World Settings** tab/section to the World Sheet (accessible in both Editor and Campaign modes) containing **`Describe on First Visit`** (default `true`).
   - Base world defaults live on [`WorldGlobalRules`](file:///home/diegolima/Git/cybercantina/backend/app/schemas/world.py#L247); active campaigns snapshot their own independent settings onto `campaigns`, editable forward-only without touching the base world or retroactively changing past turns.
2. **Branch-Accurate Container & Location Visit Tracking (`FR-2`):**
   - Track `visited_container_ids` alongside `visited_location_ids` inside `world_state_snapshots` so timeline rewinding, swiping, and branching preserve exact first-visit state for nested containers (`depth 4 → depth 1`) and locations (`depth 0`).
3. **Hybrid Cosmetic First-Visit Description Delivery (`FR-3` – `FR-5`):**
   - **Clerk / AI Turn Moves:** Attach triggered cards onto the triggering turn's `post_turn_json` (`PostTurnStateDelta.first_visit_cards`) so they render right after that turn's prose without inserting an extra turn leaf, shifting scroll position, or breaking Edit/Swipe/Delete-Last.
   - **Manual Map Moves (`override_campaign_location`):** Append a standalone `turn_kind = "arrival"` synthetic turn row carrying those cards so travel outside an AI turn appears cleanly in the feed.
   - **Turn 0 (`[Scene Start]`):** Follow campaign creation `start_focus` (`"world"` vs `"character"`), emitting container/location cards on character-focused starts (while skipping the location card—retaining parent container cards—if the character's `initial_message` uses `{location_description}` or the no-greeting fallback that embeds it).
   - **Strict Context Isolation & Auto-Collapse UI (`FR-6`):** Cosmetic-only (excluded from Zone 1–4 prompts and Clerk episodic summarization), styled with an atmospheric accent distinct from Character and Narrator turns, collapsible per card, with only the latest arrival card group expanded by default until the next turn occurs.

## 2. Scope, Boundaries & Core Invariants

1. **Cosmetic-Only / Zero LLM Context & Zero Additional LLM Calls:**
   - First-visit cards **never** enter Zone 1 (`zone1_static.py`), Zone 2 (episodic chunks), Zone 3 (`zone3_turn_entries` in [`assembler.py`](file:///home/diegolima/Git/cybercantina/backend/app/engine/context/assembler.py#L284-L310)), or Zone 4 prompt assembly, and **never** alter `WorldGlobalRules` prompt text in Zone 1.
   - Standalone map-move synthetic rows (`turn_kind = "arrival"` / `actor_id = "__arrival__"`) must be skipped in [`assembler.py`](file:///home/diegolima/Git/cybercantina/backend/app/engine/context/assembler.py#L284) and Clerk summarization.
2. **Base-World vs. Running Campaign Isolation:**
   - Editing base world descriptions or `WorldGlobalRules.describe_on_first_visit` never affects running campaigns (already protected by [`worlds.py`](file:///home/diegolima/Git/cybercantina/backend/app/db/repos/worlds.py#L718-L738) CoW freeze and campaign-owned settings snapshots).
   - Toggling `describe_on_first_visit` inside a running campaign mutates **only** that campaign's settings and applies strictly to future arrivals (never rewriting past turns or hiding previously generated cards).
3. **Timeline Branch & Rewind Fidelity:**
   - Both `visited_location_ids` and `visited_container_ids` live per turn inside `world_state_snapshots`. Rewinding/checking out an earlier branch automatically restores unvisited state for containers and locations entered later on another branch.
4. **Placeholder / Blank Description Filtering:**
   - Locations or containers whose `description` is empty, whitespace-only, or equals known auto-generated boilerplate defaults (e.g. `"A newly connected location awaiting description."`, `"A newly added structure."`, `"A newly created district or zone."`, `"An unexplored area."`) must never generate arrival cards—though visiting them still marks them visited cleanly.
5. **Non-Intrusive Scroll Behavior on Clerk Arrival:**
   - When Phase 5 Clerk asynchronously commits a move and inserts `first_visit_cards` below the completed turn output, the chat viewport must **not** programmatically jump or auto-scroll to the appended cards while the user is reading.

## 3. Functional Requirements

### FR-1: "World Settings" Tab & `Describe on First Visit` Toggle (Editor & Campaign)

- **Schema & Storage:**
  - Add `describe_on_first_visit: bool = True` to [`WorldGlobalRules`](file:///home/diegolima/Git/cybercantina/backend/app/schemas/world.py#L247) (backend & [`WorldGlobalRules`](file:///home/diegolima/Git/cybercantina/frontend/src/types/world.ts#L1) frontend).
  - Add `world_settings_json` (backing `CampaignWorldSettings` with `describe_on_first_visit: bool = True`) to the `campaigns` table (`schema.sql` + additive `ALTER TABLE campaigns` in `schema_init.py`; existing campaigns default to `describe_on_first_visit = True` or inherit their world's current `describe_on_first_visit` on load/migration cleanly).
  - On `create_campaign` ([`campaigns.py`](file:///home/diegolima/Git/cybercantina/backend/app/db/repos/campaigns.py#L107)), snapshot `{ "describe_on_first_visit": world.global_rules.describe_on_first_visit }` into `campaigns.world_settings_json`.
  - Expose `CampaignRecord.world_settings` inside `CampaignStateBundle` and add `PATCH /api/campaigns/{campaign_id}/world-settings` updating `campaigns.world_settings_json` without touching `worlds` or existing `turn_nodes`.
- **UI Placement:**
  - Add a **"World Settings"** tab inside [`WorldInspectorModal`](file:///home/diegolima/Git/cybercantina/frontend/src/components/world/WorldInspectorModal.tsx#L54) (`"base" | "map" | "lore" | "settings"`), featuring the **`Describe on First Visit`** toggle (default `ON`) with clear explanatory help text.
  - Add a **World Sheet** entry point in Campaign Mode (e.g., button in [`LiveInspector`](file:///home/diegolima/Git/cybercantina/frontend/src/components/LiveInspector.tsx) / campaign inspector header opening [`WorldInspectorModal`](file:///home/diegolima/Git/cybercantina/frontend/src/components/world/WorldInspectorModal.tsx) in `mode="campaign"`):
    - In `mode="campaign"`, Base Overview/Map/Lore reflect the campaign's active frozen world (using existing campaign map save hooks or read-only base rules), while **World Settings** saves directly to `PATCH /api/campaigns/{campaign_id}/world-settings` independently of the base world.

### FR-2: Branch-Scoped Container & Location Visit Tracking

- Add `visited_container_ids_json TEXT NOT NULL DEFAULT '[]'` to `world_state_snapshots` ([`schema.sql`](file:///home/diegolima/Git/cybercantina/backend/app/db/schema.sql#L314-L321), additive column in `schema_init.py`) and `visited_container_ids: list[str] = Field(default_factory=list)` on `WorldStateSnapshot` ([`turn.py`](file:///home/diegolima/Git/cybercantina/backend/app/schemas/turn.py), [`turn.ts`](file:///home/diegolima/Git/cybercantina/frontend/src/types/turn.ts)).
- Whenever computing effective prior visited containers for legacy snapshots where `visited_container_ids` is empty/unseeded, backfill safely on read/transition from the ancestor chains of `prev_visited_location_ids` so existing in-progress campaigns do not suddenly re-trigger starter container descriptions on the next room hop.
- On arrival at `target_loc`:
  1. Walk `target_loc.container_id` up through `parent_container_id` to build its **outermost → innermost** container ancestor chain (`[L4, ..., L2, L1]`).
  2. Compare against `prev_visited_container_ids` and `prev_visited_location_ids`:
     - Newly visited containers = ancestors in outermost → innermost order not in `prev_visited_container_ids`.
     - Newly visited location = `[target_loc]` if `target_loc.id` not in `prev_visited_location_ids`.
  3. Merge all visited location IDs and ancestor container IDs into `updated_world_snapshot.visited_location_ids` and `updated_world_snapshot.visited_container_ids` **regardless** of whether `describe_on_first_visit` is currently enabled or any description was blank (so turning the setting off while visiting room X, then turning it back on later, won't treat previously visited room X as "unvisited").

### FR-3: Multi-Card First-Visit Payload & Boilerplate Filtering

- Define shared card payload schema (`FirstVisitDescriptionCard`):
  - `entity_type`: `"container" | "location"`
  - `entity_id`: `string`
  - `depth`: `number` (`1..4` for containers, `0` for location)
  - `title`: `string` (container or location `name`)
  - `description`: `string` (the authored Atmospheric Description)
- Order cards within the arrival block **outermost container → innermost container → location** (e.g. `Layer 2 District` → `Layer 1 Building` → `Location`), skipping any node whose `description` is blank or matches known auto-placeholder text (case-insensitive trimmed comparison).
- Only emit the arrival card group if `campaign.world_settings.describe_on_first_visit` is `true` **and** at least 1 qualifying non-empty description card exists.

### FR-4: Arrival Delivery Paths (Turn 0, Clerk Moves, Map Moves)

1. **Turn 0 Campaign Creation (`[Scene Start]`):**
   - Inspect `start_focus` (`"world"` vs `"character"` selected in [`NewCampaignModal`](file:///home/diegolima/Git/cybercantina/frontend/src/components/NewCampaignModal.tsx#L105)):
     - **`start_focus == "world"`:** Skip Turn 0 arrival cards completely (world starting location's initial message/staging prose provides the opening atmosphere). Still seed `visited_location_ids` and `visited_container_ids` (all ancestor containers of starting location(s)) on `root_snapshot`.
     - **`start_focus == "character"`:** If `describe_on_first_visit` is `true`, resolve Turn 0 arrival cards on Turn 0's `post_turn_json.first_visit_cards`:
       - Emit qualifying cards for unvisited parent containers of `primary_loc` (`outer → inner`).
       - Emit `primary_loc`'s location card **unless** `character.initial_message` (trimmed) contains `"{location_description}"` OR is blank/empty (where [`campaigns.py#L144-L147`](file:///home/diegolima/Git/cybercantina/backend/app/db/repos/campaigns.py#L144-L147) falls back to embedding `primary_loc.description` verbatim inside Turn 0's prose).
       - Still record `primary_loc` and its ancestor containers as visited in `root_snapshot`.
2. **Clerk / AI Turn Movement (`pipeline.py`):**
   - When Phase 5 Clerk detects movement onto a location (`new_location_id`) and `first_visit_cards` is non-empty, attach `first_visit_cards` onto `PostTurnStateDelta` (`post_turn_json`) of the **triggering turn**.
   - Updating `post_turn_json` renders the multi-card arrival block right below that turn's prose (`TurnCard.tsx`) while leaving `Edit Last`, `Swipe`, `Delete Last`, `depth_index`, and Zone 3 untouched—and **must not** trigger any viewport scroll jump.
3. **Manual Map Move (`override_campaign_location` in `campaign_spatial.py`):**
   - When a user manually travels to `target_loc` via the Map UI:
     - If `describe_on_first_visit` is `true` and qualifying `first_visit_cards` are produced: append a standalone synthetic `turn_node` (`turn_kind = "arrival"`, `actor_id = "__arrival__"`, `user_message = ""` / `raw_prose = ""`, `post_turn.first_visit_cards = [...]`) with the updated `WorldStateSnapshot` (`active_location_id`, `visited_location_ids`, `visited_container_ids`, `scene_flags`, copied character states) as the new branch leaf.
     - Standalone `arrival` turns render as the distinct multi-card atmospheric turn block in [`ChatStage`](file:///home/diegolima/Git/cybercantina/frontend/src/components/ChatStage.tsx), omit Edit/Swipe controls (allowing clean delete/checkout revert), and are excluded from Zone 3 LLM history and Clerk episodic chunking.
     - If `describe_on_first_visit` is `false` or no cards qualify (e.g. revisiting or blank descriptions), preserve current in-place leaf snapshot behavior with zero clutter.

### FR-5: Collapsible Multi-Card Styling & Auto-Collapse Lifecycle

- **Visual Differentiation:** Style arrival turn/block containers with a distinct compatible theme surface (e.g., subtle emerald/teal or slate-teal border-left `#10b981` + tinted dark backdrop in [`styles.css`](file:///home/diegolima/Git/cybercantina/frontend/src/styles.css#L416)) clearly distinguishable from both Character turns (`--bg-card`) and Narrator turns (`.narrator-turn-card` cyan `#06b6d4`).
- **Per-Entity Card Clarity:** Each arrival entry renders inside its own collapsible card showing:
  - Header: expand/collapse chevron + layer icon/badge (e.g., `Container` / depth or `Location`) + entity **name** as card title.
  - Body: the authored **Atmospheric Description** prose (rendered cleanly).
- **Latest-Only Auto-Expand & Collapse-on-Next-Turn Rule:**
  - Identify the **latest arrival group** on `active_branch_turns` (whether attached via `post_turn.first_visit_cards` or standalone `turn_kind = "arrival"`).
  - By default:
    - Cards belonging to the **latest** arrival group **and** on the latest turn (or no newer non-arrival turn after it? Wait: *"Only the latest description cards should be extended. When the next turn takes place, all past description cards should be collapsed"*) → expand ONLY when that arrival group sits on the **latest turn** (`latestArrivalTurnId === lastTurnId`); as soon as a subsequent turn is submitted (even if that new turn doesn't visit a new location), `latestArrivalTurnId !== lastTurnId`, so **all** description cards default to collapsed! *(Wait: let's verify Turn 0 too! At Turn 0, `latestArrivalTurnId === rootTurn.id === lastTurn.id`, so Turn 0 container/location cards start expanded; as soon as Turn 1 occurs, Turn 0's cards collapse! When Turn 3 enters a new building, Turn 3's arrival cards sit on `lastTurn.id`, so they start expanded; on Turn 4, Turn 3's cards collapse!)*
  - Users can still manually toggle any card (past or current) open/closed via local per-turn UI override state; whenever a new turn arrives (`active_branch_turns.length` / `lastTurn.id` advances), clear any manual expand overrides so **all** past cards collapse cleanly as specified.

## 4. Edge Cases & UX Constraints

1. **Duplicate `{location_description}` Fallback Guard:**
   - Remember [`campaigns.py#L144-L147`](file:///home/diegolima/Git/cybercantina/backend/app/db/repos/campaigns.py#L144-L147): when `character.initial_message` is empty and no custom `opening_prose` is supplied, Turn 0 generates `f"*{character.name} stands inside {primary_loc.name}. {primary_loc.description}*"`. Treat both explicit `"{location_description}"` placeholder usage *and* that blank-greeting fallback as already providing `primary_loc`'s description (skipping the Turn 0 location card while still showing qualifying parent container cards).
2. **Checking Standalone Arrival Row vs. Previous AI Turn Edit/Swipe:**
   - When a manual map move creates a standalone `arrival` turn row at the end of `active_branch_turns`, users can click Delete/Undo on that arrival row (reverting to the turn before the map move), while [`assembler.py`](file:///home/diegolima/Git/cybercantina/backend/app/engine/context/assembler.py) skips `turn_kind == "arrival"` rows when assembling Zone 3 and Clerk skipped turns (`skip` check in Clerk chunking).
3. **Switching Campaign `start_focus` Without Persisting Unnecessary Fields:**
   - Passing `start_focus: "world" | "character"` is already part of campaign creation (`CreateCampaignRequest`); Turn 0 arrival evaluation happens atomically inside `create_campaign` (so `start_focus` doesn't even need a separate UI toggle later—only evaluated at Turn 0 seed time).
4. **Co-Present Extra Characters in Different Starting Containers:**
   - Only `primary_loc_id` (where the primary focus / player scene opens) triggers Turn 0 cards; extra party/NPC locations in `character_locations` aren't blindly printed on Turn 0, though you may decide whether `root_visited_ids` only marks `primary_loc_id` + co-located vs remote NPC rooms (`campaigns.py#L150-L153` already seeds `root_visited_ids` with `[primary_loc_id, ...extra_loc_ids]`).

## 6. Resolved Design Decisions

1. **Delivery Split (`post_turn_json` vs Standalone Row):** Clerk moves attach `first_visit_cards` to the triggering turn (`PostTurnStateDelta` / `post_turn_json`) and trigger no scroll jump; manual Map moves (`override_campaign_location`) emit a standalone `turn_kind = "arrival"` row excluded from Zone 3/Clerk.
2. **Turn 0 Rules (`start_focus`):** World-focused start skips Turn 0 arrival cards; Character-focused start emits Turn 0 arrival cards, skipping the location card (while keeping parent container cards) if the initial message includes `{location_description}` or hits the empty-greeting fallback embedding it.
3. **Nested Layers:** Emit cards for **all** nested container layers (`outer → inner`) + the location whenever they contain a valid non-boilerplate description.
